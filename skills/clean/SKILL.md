# clean

In Claude Code or Cowork, read `${CLAUDE_PLUGIN_ROOT}/docs/claude.md` first.

Typed by the owner to remove what a unit's finished or abandoned work left behind: its review worktrees and their private refs, and every builder worktree a recorded launch owns. Removing a worktree is a destructive decision and is never taken on a guess: `clean` refuses while any launch or round of the unit is not terminal, and keeps what it cannot prove, and every effect refuses without an open run card.

The owner types `/superegm:clean <unit> [--handoff <id>]`; `--handoff` names the handoff when the unit is filed in more than one open handoff (the helper refuses naming both), and is passed to `runcard open` and to every helper call below.

1. Open the card on the unit id: `superegm runcard open --skill clean --artifact <unit>`; it prints `<id>`.
2. Run the one subcommand with the owner's typed arguments: `superegm clean --unit <unit> --runcard <id>`. It removes a review worktree only when `git worktree list --porcelain` names it: the `review/<unit>/pr<n>/worktree` child, removed with force (its `pr<n>/` folder and the round records `r<n>` stay), or a legacy `review/<unit>/pr<n>` itself, removed only when it is clean (otherwise `kept <path>: uncommitted changes`, nothing signalled there, and the run goes on). It then removes each `worktrees/<unit>/r<n>/` that a launch records and git names, dirty or not (the typed skill is the owner's decision), and the empty `worktrees/<unit>/` folder. A `pr<n>` folder no worktree names, or a recorded `r<n>` git does not name, prints `kept <path>: not a worktree`; a worktree folder no launch records prints `kept <path>: no launch records it`; a tree that is a symlink, or lies below one inside `review/` or `worktrees/<unit>/`, prints `kept <path>: symlink` and is neither signalled nor removed, so a link can never reach another unit's tree. Before removing a tree it stops each process whose command is `node` or starts with `python` (matched without regard to case) and whose cwd lies inside it, as `lsof +c 0 -a -d cwd -Fpcn` lists them: SIGTERM, then SIGKILL after 5 seconds, journalled `<unit> killed <pid> <command>`; this `clean` process and its parent are never signalled. A tree stays, with a `kept` line, when `lsof` cannot list the processes (`lsof` missing, timed out, or exited non-zero with no process records: `kept <path>: cannot list its processes (<reason>)`; an exit 1 that still lists processes is used), when one cannot be signalled (`kept <path>: process <pid> cannot be signalled`) when one survives SIGKILL, or when git refuses the removal (`kept <path>: ` and the first line of git's error, such as a locked worktree); the run goes on to the next tree. The worktree list is pruned every run. `<unit> cleaned` is journalled, and `refs/superegm/pr/<n>` and `refs/superegm/pr-base/<n>` of the unit's pull requests (the recorded one and each `pr<n>` folder) are deleted, only when no tree was kept for one of the reasons in this paragraph (a symlink, `lsof`, a signal, a survivor, uncommitted changes in a legacy tree, a refused removal); `not a worktree` and `no launch records it` do not withhold them.
   `superegm clean --auto --runcard <id>` (never with `--unit`) is the form the wave and integrate skills run at their end, under their own card: the same code over every landed, merged or stopped unit that is terminal and has something to remove (a registered worktree, a recorded builder tree or a private ref), one `<unit> cleaned` line per unit cleaned. It leaves out the routine `kept <path>: not a worktree` and `kept <path>: no launch records it` lines; every other `kept` line above still prints, since it is a warning. It exits 0 always: a refused card or a missing checkout prints one `clean: <reason>` line, and any other error one `clean --auto: <unit or handoff>: <error>` line, and the run goes on.
3. Close the card: `superegm runcard close <id>`.

With `--unit` it refuses, exit 1, while a launch of the unit has no exit file and no `interrupted`, while a round is not `posted` nor `collected` with a `not run` outcome (design section 4: silence proves nothing), and under any card that is not open and uninterrupted, of the `clean` skill (the typed skill's), the `wave` skill or the `integrate` skill (the two that run `--auto`), on this unit or on the handoff's spec: an open `wave` or `integrate` card on that spec is accepted, a `clean` card opened on another unit is refused (`runcard: <id> is for <artifact>, not <this unit>`). `--auto` takes only a card on the handoff's spec.
