# SuperEGM 1.2.1-pre.1: how SuperEGM plans (§6.5), build plan

Spec: `docs/specs/2026-11-12-superegm-1.2.1-design.md` §6.5 (lines 850-1026), approved at 338e67a.
Built directly, outside the wave (§6.5 "How it ships"). Branch `build/1.2.1-pre.1`, stacked on
`spec/1.2.1` (PR #115). This plan follows §6.5's own rules: it pins contracts, Scope and acceptance
values, and leaves fixtures, helpers, private names and line numbers to the builder.

Every unit is test-first: write the test, run it and see it fail for the right reason, implement,
see it pass, then run the unit's DoD. A unit edits only its Scope paths. Tests go in the new test
file the unit names; use the existing fixtures in `tests/unit/conftest.py` and `tests/conftest.py`
and do not edit either conftest (the units run in parallel). Known baseline failure, not yours:
`tests/unit/test_review.py::test_repo_config_panels_start_with_panel_of`.

## Shared contracts

- **`amendments[]`** (written by P5, read by P4): a list under the key `amendments` in the
  handoff's `state.json` (the file `core.Store` names `state`). Absent key = no amendments. Each
  entry: `{"unit": "Uxx", "name": "<name>", "text": "<contract text>", "comment_id": <int>,
  "at": "<ISO-8601 Z, core.now_iso()>"}`; `unit`/`name` are the producing unit and the name the
  deviation names; `comment_id` is the ruling comment's id.
- **Seam comment**: an issue comment whose body starts `**Seam:**` (`**Seam:** ok` or
  `**Seam:** <what differs>`). An interface deviation's heading is
  `**Deviation (interface):** <Uxx> <name>: <what differs>`.
- **Launch `reason`**: each `launches[]` entry gains `"reason"`, one of `first`, `review`,
  `blocked`, `merge`, `harness`.

### P2 Builder orders and foreman brief
- Spec: §6.5 "The seam and deviations" (the builder's side), deviation kinds, and "The foreman"
  (what it reviews against, keeping a finding for its consequence, tracing readers and writers,
  the operative brief including amendments and rulings, a finding waiting on a ruling posted once).
- Scope: `skills/wave/references/builder_orders.md`, `skills/wave/references/foreman_brief.md`.
- Acceptance: builder orders tell the builder to post the Seam comment before Step 1 and, on a
  contract mismatch, a separate interface deviation in the heading form above; deviation kinds are
  defined by effect (`interface`, `dod`, `test` block; `other` continues) and `other` does not waive
  Scope, test-delta or TDD order. The foreman brief says the review is against spec behaviour and
  the unit's contract (Interfaces, Scope, acceptance values, rulings, amendments), not a Step's
  wording; a head is held to an amendment only when its launch started after the amendment's `at`.
- DoD: `python3 -m pytest -q tests/unit/test_link_integrity.py tests/unit/test_markdown_tables.py tests/unit/test_skill_load_limits.py tests/unit/test_wave.py tests/unit/test_foreman.py`

### P4 Builder prompt: Seam, amendments, launch reason
- Spec: §6.5 "The seam and deviations" (the `PROMPT_COMMENT_RE`/`AGED`/`keep` bullet), the

- Scope: `skills/plan/scripts/superegm/launch_builder.py`, `skills/plan/scripts/superegm/prepare.py`,

- Interfaces (produced): `launch_builder.amendments_for(st, unit: str, body: str) -> list[dict]`,
  the `amendments[]` entries whose `(unit, name)` is the unit's own (`unit == <unit>`) or a name its

- Acceptance: the prompt keeps the builder's own `**Seam:**` comment (author = `launch.builder_login`)

  not kept; `prepare.AGED` includes `**Seam:**`; the prompt carries every applicable amendment's
  text; each new launch entry has `reason` (`first` for round 1; `review` after a posted round;
  `blocked` after a ruling on BLOCKED/NEEDS_CONTEXT; `harness` for a fresh relaunch after a stall or
  setup failure; `merge` only where a merge round exists, else not produced yet);

- DoD: `python3 -m pytest -q tests/unit/test_pre1_launch.py tests/unit/test_builders.py tests/unit/test_wave.py tests/unit/test_foreman.py`

### P5 The `amend` ruling
- Spec: §6.5 "`amend`" (every bullet).
- Scope: `skills/plan/scripts/superegm/decision.py`, `skills/plan/scripts/superegm/judges.py`,
  `tests/unit/test_pre1_amend.py`.
- Acceptance: `**Ruling:** (<comment-id>) amend — <Interfaces line>` on an interface deviation is
  accepted by `decision.offered` and recorded; `decision rule` refuses it when the deviation's
  `<name>` is not in `<Uxx>`'s Interfaces lines, or the comment holds more than one deviation
  heading or a non-`interface` one; `check_ruling` refuses it from a `judges:` author;
  `judges.blocked_question` leaves `amend` out; an ordinary option ruling on a comment with several
  headings still settles them all; `decision rule` appends an `amendments[]` entry for `amend` (text
  = the owner's line) and for an option ruling that changes the interface contract (text = the
  option's text), never for `stop the unit`, one more round or a relaunch.
- Note: if `collect` does not already count an option ruling of this comment as ruling the
  deviation for `amend`, do not edit `collect.py` (P6 owns it): post a `**Deviation (interface):**`
  note in your final report instead.
- DoD: `python3 -m pytest -q tests/unit/test_pre1_amend.py tests/unit/test_judges.py tests/unit/test_u22.py tests/unit/test_foreman.py`

### P6 Foreman carry and contests
- Spec: §6.5 "The foreman", the carry, contest, `evaluate`/`settle` and outcome-word bullets.
- Scope: `skills/plan/scripts/superegm/collect.py`, `skills/plan/scripts/superegm/review.py`,
  `tests/unit/test_pre1_carry.py`.
- Acceptance: a builder contest with no ruling on a non-derived finding is re-recorded in the next
  round under the same id with `carried_from: <round>`, its `builder_contested` entry copied, and is
  not in the posted comment; a derived finding (scope, test-delta, tdd-order, dod, unruled
  deviation, unreplied, CI) reuses the previous round's id with `carried_from` only while its check
  still fails with the same claim and location, is not posted again, and is dropped once it no
  longer fails (a reverted out-of-Scope path needs no ruling); a fixable panel finding is not
  carried; carries come from the previous round only; a `contested` reply counts when its fid is
  open in the previous posted round's record (carried copies included), no longer by the round in
  the id, keeping the author, time, CI and already-ruled checks; a carried finding counts against
  convergence; a ruled one is not carried again; `review settle --finding` settles the newest round
  holding it (`locate_finding` newest first); the outcome word keeps today's order, with
  `contested_fids` and `owner_only_fids` counting carried copies.
- DoD: `python3 -m pytest -q tests/unit/test_pre1_carry.py tests/unit/test_review.py tests/unit/test_foreman.py tests/unit/test_u22.py tests/unit/test_u25.py`
